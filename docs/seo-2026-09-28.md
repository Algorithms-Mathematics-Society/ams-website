# AMS search identity and domain migration

Audit date: 28 September 2026. Canonical website: https://www.amshq.in/.

## Findings and implemented changes

The old site at https://amsociety.in/ still serves HTTP 200. Its `/about` page uses the homepage canonical and the same title and description as the homepage. The new site already has distinct page descriptions and self-referencing canonical paths, so those old patterns should not be copied.

The new bare domain redirects with HTTP 308 to `www.amshq.in`, including deep links. Previously its canonical tags, sitemap and JSON-LD pointed back to the redirecting bare domain. `SITE.url` now matches the served host and supplies metadata, schema, sitemap and robots URLs. The supplemental `llms.txt` links use the same host.

The homepage now explicitly defines AMS (Algorithms & Mathematics Society). The existing FAQ answers the old-domain continuity question and provides a direct Ascent 2026 registration answer. Both answers are available in server-rendered HTML and matching FAQ structured data. There are no hidden keyword blocks or additional thin search pages.

Organization and WebSite schema have stable identifiers. Articles reference that organization as publisher; the AMS Team author is an Organization, while named authors are people. The team roster supplies Person identity data and the actual LinkedIn links provided for each member. No degree, employment dates, legal registration status, or additional affiliation was inferred. Existing event facts were retained.

All pages now explicitly declare canonical and Open Graph URLs, site name, locale, titles, descriptions and share images. Public organization profiles appear in the footer and schema. The repository README now links to the website, contests, partnerships and LinkedIn. That README becomes an owned backlink when this commit is published on GitHub; it is not an independent endorsement.

## Verified identity sources

- The old homepage links to `https://www.linkedin.com/company/algorithms-mathematics-society/`. This returns HTTP 301 to the current AMS LinkedIn profile, whose identity and public content were verified at [AMS on LinkedIn](https://www.linkedin.com/company/amshq/).
- LinkedIn still lists `https://www.amsociety.in/` in its Website field. Updating that field requires access to the organization's LinkedIn administration.
- The [AMS GitHub organization](https://github.com/Algorithms-Mathematics-Society) serves the full organization name and hosts this website repository. It is included as a verified organization identity.
- Team profile URLs remain the user-provided links. Third-party profile restrictions do not justify guessing replacement identities.
- Derive's website is a competition property, so it is no longer described as an identical organization through `sameAs`. Its links remain available in the relevant contest content.

## Old-domain migration: prepared, not deployed

The old site is served by Vercel, according to its response headers. This repository does not establish control of that Vercel project, its domain settings, or Search Console. No DNS, old-host configuration, Search Console settings, or external profile fields were changed.

Use permanent 301 or 308 redirects on the **old host**, directly to these destinations. Handle both `amsociety.in` and `www.amsociety.in`, HTTP and HTTPS, while keeping certificates valid. Check query-string preservation and avoid redirect chains.

| Old path | Current equivalent | Evidence |
| --- | --- | --- |
| `/` | `https://www.amshq.in/` | Organization homepage |
| `/about` | `https://www.amshq.in/team` | Team and organization information |
| `/events` | `https://www.amshq.in/derive` | Old events page features AMS Derive |
| `/partnership` | `https://www.amshq.in/access` | Partnership information |
| `/faq` | `https://www.amshq.in/faq` | Organization and contest questions |

Do not blanket-redirect every old URL to the homepage. `/resources`, `/archives`, `/monthly-challenge`, `/privacy-policy`, and `/code-of-conduct` have no established equivalent here. Inventory their content, traffic, links and any nested pages first. Preserve useful resources or migrate them to real equivalent pages; return 404/410 only for content deliberately retired. The table is a starting map, not a complete old-site crawl.

After the complete mapping is deployed: verify both properties in Search Console, use Change of Address where applicable, submit `https://www.amshq.in/sitemap.xml`, inspect the homepage and representative deep URLs, and monitor indexing and crawl errors. Keep redirects for at least one year; retaining the old domain longer protects old links. Do not copy the old HTML verification token and assume it verifies a different property.

## Measurement and limits

Track branded queries `AMS`, `Algorithms & Mathematics Society`, `Algorithms and Mathematics Society`, `AMS Ascent` and `AMS Derive` in Search Console. Compare impressions, clicks, landing pages and the selected canonical over time. The bare acronym is shared by many organizations; no ranking position or timetable is promised.

Google says its AI search features use ordinary SEO foundations, including crawlable useful text and structured data that matches visible content. `llms.txt` is maintained as a supplemental summary; it is not a special Google requirement or evidence of inclusion in an assistant's answers. Google retired FAQ rich results in May 2026. FAQ markup remains a description of visible answers, not a Google rich-result opportunity.

Automated repository checks validate generated metadata, entity relationships, schema shapes, visible FAQ parity and sitemap consistency. They do not certify eligibility for Google's rich results. After deployment, also inspect the live URLs with the Rich Results Test and Search Console.
